# 架构、模块与资源规划

## 1. 决策与约束

- Go 模块化单体，单进程 API；初期不支持多个 API 实例共享 SQLite。
- 标准库 `net/http` 路由与 HTTP 服务，`log/slog` 结构化日志；JSON 使用标准库。
- GORM 处理常规查询、映射和事务；不依赖生产 `AutoMigrate` 管理版本。
- Go 工具链在 P1 选择当时仍受支持的稳定版本并锁定；依赖锁定于 go.mod/go.sum。不在规划文档猜测未来版本号。
- SQLite 驱动优先验证纯 Go 的 GORM 兼容方案，实现 CGO_ENABLED=0 交付；备选为 CGO 驱动及受控静态构建。最终选择必须留下目标 NAS 构建、事务和资源测量记录。GORM 官方 SQLite 方言所采用的驱动不能被误认为默认纯 Go。
- PostgreSQL 方言和初始化入口从第一阶段具备，测试环境启动 PostgreSQL；NAS 默认无需安装它。
- 按边界定义小接口，不给每张表机械添加 Repository，不建立自行扩展的通用 ORM。

## 2. 建议代码布局

```text
cmd/cyapi/                     # CLI、启动、依赖组装
internal/
  config/                      # 配置加载、路径解析、校验
  server/                      # HTTP 路由、中间件、兼容 DTO
  auth/                        # 新账号、验证码、会话与限流；首期无扫码
  playlist/                    # 本地/同步歌单、快照、幂等操作
  library/                     # 收藏、账号平台绑定
  playback/                    # 播放状态、听歌时长、播放次数
  music/                       # 搜索、歌词、发现页的业务编排
  provider/
    netease/ qq/ kugou/
                               # 首期仅网易云、QQ、酷狗协议
  outbound/                    # HTTP 连接池、超时、限并发、目标校验
  persistence/
    models/                    # GORM 存储模型
    repositories/              # 查询与原子操作，普通实现共享
    dialect/                   # 少量不可移植操作与数据库初始化
    migrations/
      sqlite/ postgres/        # go:embed 嵌入的版本化 SQL
  sources/                     # 文件读取、版本选择、GitHub 同步
  cache/                       # 有界 TTL 缓存与请求合并
  mail/                        # Brevo HTTP 邮件适配
  maintenance/                 # 清理、备份等管理子命令
  compatibility/               # 旧占位接口响应
  buildinfo/                   # 版本、commit、构建时间
configs/                       # 无秘密的示例配置
packaging/                     # 后续 systemd/Compose/镜像构建资料
contracttest/                   # HTTP、持久化、上游样本契约
```

按功能设置文件即可，不为目录数量牺牲可读性。领域对象与 API DTO 不携带 GORM 标签；GORM 模型不直接序列化给客户端。

## 3. 依赖边界

HTTP 只负责解析、鉴权上下文、调用业务、编码；不直接写 SQL或发平台请求。业务模块规定所有权、状态机、幂等与原子性；存储实现隐藏 GORM、SQL 和驱动错误。Provider 隐藏平台 Cookie、签名、请求路径与响应差异。

可按业务定义 `AddLocalItems`、`ActivateSnapshot`、`ConsumeCodeAndResetPassword` 等原子操作接口。跨表事务在一个存储操作内完成，避免业务层暴露 `*gorm.DB` 或各 Repository 自行提交造成部分成功。单表普通查询无需过度抽象。

依赖在 cmd 中显式组装，不使用全局数据库、全局可变配置、自动依赖注入框架。每次请求传递 context；配置启动时校验后作为不可变值使用。

## 4. 平台请求与缓存

- 平台按 Search、Lyrics、Resolve 等小能力组织；B 站和抖音不进入首期模块。
- 共享可复用 Transport；平台凭据按目标附加，不放入跨域通用默认请求头。
- 搜索保留当前总预算 12 秒、单次最多 8 秒及特定回退语义；歌词保留当前共享 7 秒预算。不能在统一客户端中给这些请求自动增加重试。
- 普通请求仅对确认可安全重试的操作做有上限重试；客户端取消立即取消上游；JSON 解析也在总预算内。
- 平台 JSON 响应限制大小；首期不提供媒体中转接口。
- 缓存仅用于明确可共享的内容。用户、Token、二维码、验证码、统计禁止共享缓存；键含平台、质量、分页及必要的凭据配置版本，不能包含原始秘密。
- 请求合并必须有独立有界生命周期：首个调用者取消不应错误取消其他有效等待者；没有等待者或到期后终止任务。
- TTL=0 关闭对应缓存；显式刷新绕过；上游失败不伪装为空结果；歌词只有明确无歌词时才短期负缓存。

## 5. 初始资源限制（待测量调优，非性能承诺）

| 项目 | 首轮测试起点 | 说明 |
| --- | --- | --- |
| API 实例 | 1 | 先不启用多副本 |
| 缓存值总量 | 16 MiB | 同时设置 2000 条、单项 1 MiB；键与对象开销另计 |
| 平台请求并发 | 每平台 8、全局 32 | 等待受请求 deadline 控制 |
| SQLite 连接 | 初始单连接 | 正确性优先；测量后再分离小读池与单写池 |
| 普通请求体 | 1 MiB | 大批量歌单按契约配置独立上限 |
| 普通上游响应 | 8 MiB | 大歌单分页或单独上限，不静默截断 |
| 音源同步 | 单实例、下载并发 2 | 大小和文件数限制见同步文档 |

SQLite 单连接模式必须避免事务内误用根 DB 触发死锁。最大连接数为 1 不代表物理连接永久不变；所有新建和重建连接都必须执行并校验连接级初始化，细节见数据库文档。并发、缓存满额、上游变慢、客户端断开要测试资源释放。没有真实负载时不宣称固定内存占用或 QPS。

## 6. 认证与安全边界

采用全新账号体系，不导入旧密码哈希、不接受旧 Token，也不实现旧四段 Token 兼容。首期新登录签发单一格式的 HMAC Token，使用独立生成的 AUTH_SECRET；签名、期限和 token_version 校验用于当前系统会话。每个受保护请求读取 token_version，改密立即撤销当前系统旧会话。新密码使用 Go bcrypt，明确 UTF-8 字节长度上限并限制验证并发；不为旧 bcryptjs 哈希添加兼容分支。扫码登录和二维码存储不进入首期功能。

公网代理链覆盖真实 IP 头，应用只信任配置中的代理。B 站、抖音和媒体代理不进入首期；以后新增用户可控出站 URL 时，另行落实域名、实际连接地址和重定向约束。

现有 sponsors/create 接受 body.userId 并直接标记赞助，不应作为普通登录用户可写接口照搬。默认关闭该写入能力或仅允许明确管理员调用，并在兼容差异中记录；支付占位接口不表示支付已启用。

## 7. 可观测性与退出

日志包含 traceId、方法、路径、状态、耗时、平台阶段、缓存状态。默认不记 query、Authorization、Cookie、密码、验证码和完整上游响应。数据库慢查询日志也不得泄露绑定值。

提供存活与就绪检查：存活不依赖外网；就绪检查 schema 与数据库基本可用性。GitHub 暂时失败不导致 API 不就绪；未配置平台凭据只影响相关功能。记录音源上次成功版本和失败原因。

退出顺序：停止接收新请求、停止后台任务、在有限宽限期内完成请求、取消上游、关闭数据库。备份和同步使用独立子命令，只有需要 API 的 serve 才初始化完整服务依赖。
