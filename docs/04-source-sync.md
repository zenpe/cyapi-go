# 音源存储与 GitHub 同步

## 1. 最终方案

彻底移除 R2：NAS 计划任务调用同一 Go 二进制的 sync-sources，获取 GitHub 文件后发布本地版本；serve 从本地提供兼容的公开列表与下载。API 不执行脚本，正常下载不要求 GitHub 实时在线。

现有定时任务不在已查看的 cyapi-workers 仓库中。GitHub 仓库、分支、目录、筛选/重命名、合并来源、更新频率、认证方式都尚未核实；实现不能擅自猜测。P4 先读取旧任务配置并形成无秘密的 sources manifest。

## 2. 目录与发布模型

```text
cyapi/
  cyapi
  config.yaml
  data/
    cyapi.db
    sources/
      current.json                  # 原子替换的版本指针，只供服务读取
      sync.lock                     # 进程互斥锁
      versions/
        <generation>/
          manifest.json             # 来源 commit、摘要、路径、同步时间
          files/
            example.js
            group/another.js
      staging/
        <attempt>/                  # 尚未发布的下载结果
```

源目录与程序可放在同一部署根目录，必须独立子目录；配置也允许指定其他本地路径。staging 与 versions/current.json 要在同一文件系统，确保 rename 的发布语义。不采用逐文件覆盖线上目录。

serve 每次操作先解析并固定 generation，后续文件读取都在该版本内；跨进程同步后无需重启 API。current 指针禁止指向 sources 外部；不通过可任意跳转的用户 symlink 读取文件。

## 3. 完整同步步骤

1. 获取 OS 级进程互斥锁，已在同步则明确返回“跳过”，不能同时覆盖版本；锁在进程崩溃后可释放，不仅依赖永不清除的标志文件。持锁后先执行下述遗留 staging 回收和空间预算检查，通过后才创建本次 attempt 目录；所有同步入口必须使用同一把锁。
2. 读取配置并将每个来源的 branch/tag 解析成确定 commit。单次同步的清单和下载全部使用对应 commit，避免分支移动导致混合版本。只有上游版本集合、有效同步配置摘要、当前已发布版本完整性三项同时符合下述条件，才允许跳过；ETag/304 只能证明对应远端资源未变化，不能单独作为跳过依据。
3. 枚举允许目录下的 .js，完整处理分页及 Git tree 截断。枚举不完整时失败；不把 API 限流/鉴权错误当成空列表。
4. 用并发和大小限制下载到 staging，只接受配置允许的 GitHub 下载主机/重定向。拒绝绝对路径、..、控制字符、反斜杠、符号链接、archive 越界条目和规范化后重名。
5. 保留文件字节，核对 HTTP 状态、来源元数据和 SHA-256，拒绝错误页或明显不是目标文件的响应。自己的摘要提供完整性/变更记录，不等于证明上游脚本可信；来源仓库必须明确批准。
6. 生成 manifest，记录 manifest 格式版本、每个来源标识与 commit、同步配置摘要以及每个文件的相对路径/大小/SHA-256。所有预期文件下载成功才允许发布；多来源路径冲突报错，不使用不确定的“最后写入者获胜”。
7. 落盘并完成目标系统必要的 flush，先将完整 staging rename 到 versions/generation，再通过临时指针文件 rename 原子替换 current.json。发布失败仍保留旧 current。
8. 记录同步成功版本、耗时和文件数。回收旧版本时避开活动读取，并保留最近两个成功版本及至少 24 小时宽限；清理失败不使成功发布回滚。

首次无版本且同步失败：接口返回明确 503。曾成功同步后再失败：继续提供旧版本并记录失败状态，不返回空列表。首次仓库确实为空与枚举错误要区分；默认拒绝将非空版本替换成空版本，只有显式 allow_empty 才能发布空版本。


### 3.1 跳过判断与本地修复

同步配置摘要由规范化后的仓库身份、ref、输入目录、过滤规则、路径映射/重命名规则、多来源合并规则及影响输出的同步格式版本生成。采用稳定编码和 SHA-256；包括输出相关默认值，排除 token、时间戳、日志级别等秘密或无关配置。多来源标识排序稳定，保留有业务含义的规则顺序。

每轮在持锁状态下比较当前已发布 manifest：上游来源集合与 commit 全部一致、配置摘要一致、current 可解析且指向合法 generation、manifest 版本可识别、files 中路径集合与 manifest 一致，所有文件大小和 SHA-256 匹配且没有符号链接，才能报告 unchanged。完整性检查流式读取且不把所有文件装入内存。

配置变化、文件缺失/损坏、current 或 manifest 丢失/无效，都不能因为远端 304 而跳过；重新获取完整清单并在新 generation 中重建，禁止原地修补正在服务的版本。远端不可用时如有经过校验的旧版本可用则继续分发；不能把已损坏的文件作为成功响应发出，无有效版本时返回明确不可用。可增加 --force 绕过跳过优化，但仍必须遵守锁、来源、容量和发布校验。

### 3.2 失败回收与空间上限

- 正常失败、取消或超时：在退出处理里清理本次 attempt 目录，保留结构化错误信息，不保留完整失败下载作为默认调试资料。进程被强制终止后的回收由下一次持锁任务完成。
- 下次任务取得独占锁后，扫描应用管理的 staging 直属 attempt 目录；确认没有其他同步进程持锁，验证规范化绝对路径位于 staging 内且没有符号链接/重解析点后回收。仅按文件年龄不能证明目录无活动写入。sync.lock 在 staging 外，不能随清理删除。
- 已 rename 到 versions 但未成功切换 current 的版本作为孤立版本处理，按版本 GC 规则回收；GC 必须保护 current、保留版本及活动读取。不能因指针发布失败删除仍被服务使用的版本。
- 初始 staging 总预算为 100 MiB，与单代最大量一致；流式下载时持续累计写入量，超预算立即停止并清理。每轮预检可用空间至少覆盖本次最坏下载量再加可配置保留余量（起点 1 GiB）；磁盘查询失败或余量不足时停止同步。运行中继续检查预算和空间，预检不代表可以无限写入。
- 遗留目录因权限/IO 错误无法回收时，记录路径和占用，任务失败并停止创建新的 attempt；禁止每轮继续堆积。空间不足时不删除当前有效音源或数据库腾位置。该保护不能阻止其他进程写满磁盘，因此需保留部署级磁盘监测。

失败回收测试需连续运行至少 10 次“下载中途失败”和“进程终止后重试”：每次正常失败后无本次残留，崩溃残留在下一次持锁任务创建目录前被回收；staging 实际总量始终受预算约束。还需验证清理失败停止下载、越界/链接目录拒绝处理、API 当前版本不受影响及数据库仍可写。

## 4. 删除、路径和客户端兼容

默认按完整 manifest 镜像上游：完整成功同步后，上游已删除的文件不再出现在当前列表；下载已删除路径返回 404，客户端刷新列表。同步失败不得触发删除。客户端已保存的本地脚本不会被服务自动删除。

用户提交 path 只解码一次并按组件校验，防止编码绕过和前缀字符串误判；实际解析结果必须位于 generation/files 内。符号链接拒绝，静态文件根目录仅暴露 files，不能暴露数据库、配置、manifest 或 staging。

文件名支持空格、中文和嵌套目录，列表稳定排序；downloadUrl 使用配置的 public_base_url，避免 Host 注入和容器内部地址。接口保持当前字段与 Content-Type/no-store；内容摘要生成 ETag。

## 5. 默认限制与调度建议

建议起点：每 6 小时同步一次，可配置；任务总超时 10 分钟；下载并发 2；单文件上限 5 MiB；文件数上限 1000；一代总量上限 100 MiB。全部是待核对真实仓库后的初始预算，超过限制返回明确错误，不能截断后发布。

空间检查与失败回收按 3.2 执行，需覆盖 staging、新版本、保留版本及安全余量。API 文件下载采用流式处理，不将整套脚本常驻内存。认证 token 由环境变量/受限文件提供，不写入 URL、日志或同步 manifest。

GitHub 429/5xx 按 Retry-After 和有限退避重试；重复失败由 NAS 调度下一次执行，不做无限热循环。NAS 上行决定脚本分发能力，不能套用 R2 的带宽假设。

## 6. 子命令目标（待实现）

```text
cyapi sync-sources --config /path/config.yaml
cyapi sources status --config /path/config.yaml
cyapi sources rollback --generation <id> --config /path/config.yaml
```

sync-sources 仅初始化源配置/HTTP/文件系统，不要求打开业务数据库。rollback 校验旧版本完整性后原子切换指针，并与同步共享锁。

验收涵盖：增改删、嵌套路径、特殊文件名、未变化跳过、相同 commit 下配置变更、本地文件缺失/篡改/指针丢失后的重建、连续失败及崩溃后的 staging 回收、清理失败停止下载、仓库移动分支、限流、部分下载失败、空仓库、磁盘满、并发任务、进程中断、跨进程更新可见、正在下载时发布、回滚。日常运行无 R2 SDK、R2 凭据及 Cloudflare 请求。
