# 按平台自动推荐音源

QQ、网易分别维护标准音质（128k）推荐。后台检测与发布脚本，客户端在本地解析，不改变当前播放。

## 简化规则

- 尚无推荐：逐个检测候选，首个符合资源检查条件的脚本立即发布，结束该平台本轮剩余搜索。
- 已有推荐：日常只检测当前脚本；符合条件就继续使用，不为排名而替换。
- 当前推荐异常：一分钟后复测一次，复测恢复则保留；仍异常才搜索替代者。检测环境限制单独显示，不作为源失效依据。
- 替代搜索每批只检测一个候选及当前脚本；当前脚本恢复则停止搜索，否则候选合格就发布，并结束该平台本轮剩余搜索。另一平台独立继续。
- 其他候选低频检测，正常推荐在这类检测中不会被替换，也不会随每个候选重复下载。默认周期七天。

不再使用候选两轮确认、同曲覆盖增益及候选排名换源。结构和时长检查标准保持不变；符合条件不代表已经解码、歌曲身份可靠或全部歌曲都能播放。

## 配置

```yaml
source_recommendation:
  enabled: true
  automatic:
    enabled: true
    full_interval: 168h
    watch_interval: 3h
    min_samples: 3
    min_positive_samples: 2
    evidence_max_age: 6h
```

`automatic.enabled` 默认关闭，启用不依赖 `admin.enabled`。默认至少三首样例，其中至少两首符合检查条件；参数可配置。旧配置的 `confirmation_rounds` 继续接受但不再生效，可删除。已有显式设置的 `full_interval: 72h` 保持三天，不会自动改写为七天。

后台串行复用 source-check Controller，不与手动任务并跑。Linux worker 必须有 cgroup v2 内存硬限制。网络策略沿用公网目标检查，不继承升级器代理。单次任务、扫描分片预算、失败退避继续生效。

升级后保留已发布清单和累计任务/读取量，清除旧候选确认状态，并安排一次检查及搜索；无推荐的平台不必等待旧的全量周期。当前推荐首次异常的计数可跨重启保留，样例/检测器/目标变化或证据过期会重新判断。暂停、回退及发布前的输入校验继续使用控制版本与存储锁。

## 接口和管理

- `GET /lx/recommendation-plan`：按 qq/netease 的不可变清单，ETag/304；未发布返回 404。
- `GET /lx/recommendation-scripts/{sha256}.js`：按哈希下载引用中的脚本。
- `GET /lx/recommendation-status`：脱敏检查结果。
- `POST /lx/recommendation-check`：当前后端普通登录用户申请提前巡检；202 受理，200 合并，409 关闭/暂停/手动任务忙碌，429 携带 Retry-After。全局每三十分钟最多受理一次，重启后有效，不绕过故障退避或自动更换正常推荐。
- 管理接口位于 `/admin/source-recommendations/automatic`，支持暂停、恢复、立即巡检、历史和回退并暂停。

页面区分当前正常、异常待复测、搜索替代和已发布；首次无推荐不显示证据已过期。任务数和资源字节数只累计已收尾批次，当前批次不计入；读取量不包含脚本解析接口流量。历史决策中的旧确认轮数保留用于审计，不影响新流程。

状态仍位于 `automatic/`，复用原清单、归档、队列和原子发布。历史保留、备份恢复、旧版手动推荐和客户端协议保持兼容。

## 验证

运行 `go test ./...`、`go vet ./...` 和 `node --test internal/admin/web_test.cjs`。受控回归覆盖首次发布与停止搜索、正常巡检只读当前源、异常复测恢复、连续异常替换、检测环境限制、低频候选检查、升级旧状态及持久化计数。

确定性测试不代替 NAS 实际隔离、公网音源和客户端播放验收。
