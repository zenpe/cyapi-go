# 按平台自动推荐音源

QQ 与网易云分别维护标准音质（128k）的推荐脚本。后台串行检测、比较相同样例的证据并经过多轮确认后发布；适配客户端下载清单和脚本，在本地解析。首次启用后不需要每日登录后台操作。

## 配置

```yaml
source_recommendation:
  enabled: true
  automatic:
    enabled: true
    full_interval: 72h
    watch_interval: 3h
    min_samples: 3
    min_positive_samples: 2
    confirmation_rounds: 2
    evidence_max_age: 6h
```

默认 automatic.enabled 为 false。启用依赖公开推荐入口，不依赖 admin.enabled。自动任务复用现有 source-check worker，要求真实的内存硬限制；Linux 必须完成 cgroup v2 委派，未隔离的手动诊断不会用于自动发布。网络策略沿用公网目标检查，不继承升级器代理。

最小样例数与正面证据数是可配置的证据底线，不是固定通过率标准。当前脚本的正面歌曲须全部保留，并且候选持续新增至少一首覆盖或可验证证据才会替换。共同歌曲失败不会一票否决；环境限制不能证明候选更好。两轮至少间隔十分钟，过期、暂停/恢复、重启或输入变化重置未完成确认。

资源检查通过只表示结构及现有时长检查符合条件，不保证实际解码、歌曲身份或所有客户端网络可播放。没有更好候选时保留已发布脚本，显示退化、受限或证据过期状态。

## 运行与管理

首次启用自动扫描。全量扫描按平台分组，单批预算最多九十分钟，一次扫描工作片段最多三小时；未完成的队列至少十分钟后继续。优先复核，再巡检，再继续全量。共享 Controller 保证不与手动任务并跑。

管理页面显示各平台证据、确认进度、下次巡检和当前批次进度，支持暂停/恢复、立即巡检、历史与回退。回退创建新清单并同时暂停，防止旧任务覆盖。总开关关闭时不能从页面开启调度；只要公开入口仍开启，已发布清单和脚本仍可读取。

任务数与资源字节数为调度器收尾报告时累计，不含脚本调用接口的网络流量；服务崩溃时尚未记账的批次可能未计入。实际流量与 CPU/内存需结合 NAS 监控观察。

## 接口与数据

- `GET /lx/recommendation-plan`：format=1、planId、quality=128k、按 qq/netease 的 targets；ETag/304；未发布 404，数据损坏 503。
- `GET /lx/recommendation-scripts/{sha256}.js`：已保留清单引用的不可变脚本，客户端校验原始字节哈希。
- `GET /lx/recommendation-status`：脱敏的平台证据摘要，健康变化不生成新清单。
- `POST /lx/recommendation-check`：当前后端普通登录用户可申请提前巡检，无需管理员权限。202 `accepted` 表示已持久化受理，200 `already_running` / `already_requested` 表示合并；409 表示关闭、暂停或手动任务忙碌，429 携带 `Retry-After`。全局每 30 分钟最多受理一次，跨重启有效；保留故障退避、分片预算及推荐确认间隔，不保证立即更换推荐。客户端的“检查更新”仍只读取已发布清单。
- 管理接口位于 `/admin/source-recommendations/automatic`，沿用管理员鉴权及请求来源保护；control/check/rollback 使用清单和控制版本进行冲突检测。

状态位于推荐数据目录的 `automatic/` 下，包含单一提交指针、不可变清单和决策、可恢复的调度队列。备份包含这些文件及所有保留清单引用的归档脚本，包括仅自动模式和首次发布前的暂停状态。历史保留最多一百项/三十天，当前及上一版受保护；旧版推荐清理也保留自动清单引用。恢复后保留已发布版本并重新建立确认。

## 验证与部署

本地验证：`go test ./...`、`node --test internal/admin/web_test.cjs`。自动调度与发布测试使用受控结果和注入时钟，不依赖公网源偶然可用。

先部署兼容后端、再部署适配客户端，最后启用 automatic。客户端在音源设置选择一次自动推荐，随后定期更新；旧客户端仍使用原来的单脚本推荐入口。NAS 首轮检查内存隔离、批次耗时、流量和停止回收，Windows 验证混合歌单及切换期间继续播放。本次代码实施未代替实际部署验收。
