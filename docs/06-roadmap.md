# 实施阶段、测试和发布验收

## 1. 执行原则

用户已授权在 cyapi-go 开始代码实施；上线、发送邮件和迁移线上数据仍不在本次范围。后续按阶段实现，每阶段提交可运行结果、测试证据、已知差异与下一阶段输入。默认单 Agent 串行推进；只有明确要求并行 Agent 工作时才安排模块所有权，避免同时改数据库模型和公共 DTO。

实现前以 README 指定源码为起点，记录实际基线 commit 和工作区差异。旧项目保持作为兼容参考，不在迁移中顺手修改旧线上代码。新项目 Git 初始化、CI 和发布配置在 P1 实施。

避免一次性生成所有模块再统一调试。每个阶段都需覆盖失败路径；不能用占位返回或跳过失败测试宣称完成。

## 2. 阶段与依赖

| 阶段 | 输入 | 主要产出 | 验收门槛 |
| --- | --- | --- | --- |
| P0 契约冻结 | 当前代码、客户端行为 | 补全路由契约、脱敏 fixtures、差异清单 | 所有路由有归属及真实/占位分类 |
| P1 基础与驱动验证 | P0、NAS 架构 | Go 骨架、配置、日志、双数据库初始化、迁移 CLI、构建 | 目标 NAS 可运行；双库 schema/基础事务测试通过 |
| P2 账号与用户数据 | P1、业务契约 | 邮箱注册、密码登录、找回密码、限流、收藏、歌单、播放统计 | 并发/幂等/快照/撤销等关键契约通过双库测试 |
| P3 平台与兼容路由 | P1、P0 fixtures；鉴权依赖 P2 | Provider、搜索、歌词、发现、范围内兼容响应 | mock 回归通过，真实平台可选 smoke 有独立报告 |
| P4 本地音源 | P1、旧 GitHub 任务资料 | 同步 CLI、版本发布、本地列表/下载 | 失败保旧、并发发布、路径校验和回滚测试通过 |
| P5 NAS 集成与迁移演练 | P2—P4、全新测试数据、VPS 参数 | 空库初始化、部署资料、frp 验证、资源报告、恢复演练 | 客户端全链路和数据校验通过，无未解决上线阻断项 |
| P6 正式切换 | P5、维护窗口 | 新账号上线、最终备份、入口切换、观察报告 | 数据一致、主要流程可用、回滚路径明确 |

P3 与 P4 的业务依赖可独立，但不因此默认启动并行 Agent。估时需在 P1 驱动验证和 P0 契约清单完成后给出，不能按文件数量承诺迁移天数。

## 3. P0：契约冻结

- [ ] 逐项补全路由清单的鉴权、请求、响应、状态码、缓存和副作用。
- [ ] 保存搜索分页/超时/QQ 回退、歌词状态、新系统 Token、音源路径等脱敏样本。
- [x] 确认全新账号体系；D1 结构与快照不再作为首期依赖，扫码登录暂不实现。
- [ ] 记录目前已知安全差异：真实 IP、CORS、赞助写入口及明确排除的 B 站/抖音。
- [ ] 记录当前 tests 六类覆盖范围，并为歌单标出新增测试需求。

## 4. P1：先验证最难替换的基础

- [ ] Go 版本和依赖锁定；README 明确构建和运行命令。
- [ ] SQLite GORM 驱动验证纯 Go/CGO 选择，提交决定及原因。
- [ ] 对应 NAS 架构编译并实际启动，检查动态依赖、证书和文件权限。
- [ ] 双库 baseline migrations、版本校验、迁移互斥和拒绝不兼容 schema。
- [ ] 验证唯一冲突、NULL/零值、批量 ID、事务失败回滚和外键。
- [ ] 强制 SQLite 物理连接重建，核对每连接 PRAGMA，实际验证孤儿外键被拒绝及锁等待受限。
- [ ] config/secret/path 解析、健康检查、优雅退出、trace 日志。

如果驱动验证不通过，在此阶段调整，不应等业务全部写完后再改数据库访问方案。

## 5. P2：数据一致性优先

- [ ] 新账号注册、单一 HMAC Token 格式、新密钥隔离、bcrypt 输入边界、token_version 撤销；拒绝旧系统 Token。
- [ ] 邮箱验证码一次性消费，过期/并发/改密重放测试；扫码路由不实现、不暴露可用入口。
- [ ] 限流预占、退款、跨窗口和 IP 伪造测试。
- [ ] 收藏和平台绑定的用户隔离。
- [ ] 本地歌单 CRUD、默认歌单唯一、幂等请求和操作结果重放。
- [ ] 批量增删、替换、重排及 revision 冲突；所有权不可跨用户。
- [ ] 同步快照的完整性、重复项、旧同步隔离及失败恢复。
- [ ] 播放状态、统计累加、排名稳定、分页边界和私有缓存头。
- [ ] 相同业务用例在文件 SQLite 和 PostgreSQL 上执行；不能 mock 掉事务来验收。

## 6. P3：按平台完成垂直链路

顺序建议网易云 → QQ → 酷狗，每个平台同时完成签名、请求、解码、HTTP 响应和错误映射。优先参考 fixtures，无须为自动回归调用真实用户 Cookie。

- [ ] 搜索 12 秒总预算、歌词 7 秒总预算、无错误自动加重试。
- [ ] QQ 回退/分页、指纹和 hasMore；真实空结果与上游失败区分。
- [ ] 公共内容缓存、歌词负缓存、缓存容量与并发请求合并。
- [ ] B 站、抖音与 MPD 路由明确排除，不将旧代码存在当作已支持功能。
- [ ] compat 全量路由保持明确占位语义，赞助写入口按权限决策处理。
- [ ] 邮件 mock 完成；真实邮件仅在测试收件人与发送范围明确授权后验证。

## 7. P4：音源同步独立验收

- [ ] 核对原定时任务的仓库、路径映射、过滤和更新规则。
- [ ] 固定 commit 获取、分页/截断检查、大小和目录限制。
- [ ] 单进程锁、staging、版本 manifest、current 原子切换。
- [ ] 完整增改删、上游故障保旧、空版本保护、磁盘满和进程中断。
- [ ] 相同 commit 下变更过滤/路径映射仍重新发布；远端 304 时本地文件损坏、缺失或指针无效仍触发完整重建。
- [ ] 连续至少 10 次中途失败与进程终止重试，验证 staging 回收及总量预算；无法回收时停止下载，当前音源和数据库不受影响。
- [ ] 列表和下载旧契约：嵌套、特殊文件名、404、503、原始字节。
- [ ] 与旧任务输出对比，记录允许的路径/内容差异。

## 8. P5：资源与压力验证

测试硬件、架构、Go/驱动版本、数据规模、缓存容量、并发、总请求数、磁盘和网络必须进入报告。不能把下面的建议起点当作用户真实规模。

初始固定数据集建议：100 用户、每用户 10 歌单、总计 10 万歌单条目、10 万播放记录；用 mock 上游隔离外网耗时，再做少量 NAS 实际出口验证。

| 场景 | 起点 | 必须观察 |
| --- | --- | --- |
| 空闲 | 就绪后 10 分钟 | RSS/堆、CPU、goroutine、FD |
| 混合 API | 20 并发、30 分钟，读为主并穿插写入 | P50/P95/P99、错误率、Busy、数据正确性 |
| 歌单集中写 | 并发同步/重排/统计 | 无丢更新、无部分快照、写队列可控 |
| 音源同步 | API 读取期间更新/失败/回滚 | 无半文件、无版本混合、接口稳定 |
| 断网与重启 | 中断上游/frp、杀进程后启动 | 重连、数据库恢复、pending 操作恢复 |

首轮目标建议：应用空闲 RSS 不高于 80 MiB、上述混合负载峰值不高于 200 MiB；纯本地常规 CRUD P95 不高于 200ms；有效请求无数据错误、无未处理 SQLITE_BUSY。它们是测试起点，不是性能承诺；P1 根据实际 NAS 调整并记录理由。峰值包含缓存和同步场景，不能只报 Go 堆代替 RSS。

长时间测试后连接/FD/goroutine 不持续增长；停止负载后资源趋于稳定。上游真实超时单独归因，不通过删除这些请求来美化总体指标。GOMEMLIMIT 是软限制，不代替容量设计或容器硬限制。

- [ ] 目标 NAS 上构建/运行资料齐全，CA 证书与时钟正确。
- [ ] 双公网客户端真实 IP、伪造头、入口绕过、下载 URL HTTPS 验证。
- [ ] 空库初始化、新注册全流程及备份恢复演练；确认未导入旧账号或旧凭据。
- [ ] 客户端重新注册/登录、搜索、收藏、歌单、播放地址解析、音源更新联调。
- [ ] SQLite 一致性备份恢复到新路径，实测恢复时间。
- [ ] 使用新二进制/新镜像执行新增迁移后切换版本；演练迁移失败和启动失败，确认恢复旧数据与旧程序的路径。
- [ ] 编译二进制和发布包均不含秘密，不依赖 Cloudflare SDK/binding。

## 9. P6：发布门槛与证据

上线阻断项：认证/越权、数据丢失、旧同步覆盖新数据、错误凭据发送、部分音源发布、无法恢复备份、新账号初始化未验证。已知占位接口不冒充新增能力；上游暂时不可用必须明确记录。

实施时建议产生以下证据文件（现在尚未生成）：

- docs/evidence/contract-matrix.md：全路由覆盖与有意差异。
- docs/evidence/database-parity.md：双库测试与驱动决定。
- docs/evidence/initialization-report.md：新库 schema、初始数据校验和备份恢复，不含秘密。
- docs/evidence/nas-benchmark.md：硬件、负载和资源原始摘要。
- docs/evidence/recovery-drill.md：恢复步骤、耗时、失败处理。
- docs/evidence/release-checklist.md：停写、切换、回滚、观察和资源清理状态。

单个任务交付至少包含：实现范围、相关契约、修改文件、实际运行的验证、未完成项。不以“应该能运行”替代 NAS 与数据库的实测证据。
